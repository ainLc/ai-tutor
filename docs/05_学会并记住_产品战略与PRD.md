# AI 私教：学会并记住

> 产品战略与需求文档（PRD）  
> 版本：v2.0｜日期：2026-09-08｜角色：产品｜状态：指导后续研发  
> 本文档取代 `01_产品需求PRD.md` 中的产品方向；旧文档保留作 MVP 史记录。

---

## 1. 产品要回答的一句话

用户打开一门课，不是来「看完」的，而是来 **把这门课真正学会，并且过几天、过几周还能想起来、讲得出来、用得上**。

**产品承诺：**

> 上传你要学的资料，得到一位按这份资料授课的私教：先把你讲懂，再拦住你往下赶，最后按遗忘曲线把该记的东西送回你面前，直到你真的记住。

旧定位停在「会讲、会画、会问」。那只能证明用户 **当时好像懂了**。本版把产品从「AI 讲课工具」升级为 **「掌握学习 + 长期记忆」系统**。

---

## 2. 为什么现在必须改方向

### 2.1 用户的真实失败，不是「没人讲」

自学技术资料、内部培训、考证材料时，失败通常分两段：

| 阶段 | 用户以为发生了什么 | 实际发生了什么 |
|---|---|---|
| 看的时候 | 「讲得很清楚，我懂了」 | 再认（recognition）成功，提取（recall）并未建立 |
| 过几天 | 「印象还在」 | 细节、步骤、对比关系已经掉了 |
| 要用的时候 | 「当时明明学会了」 | 无法在新情境中提取，等于没学会 |

当前产品已经能：拆课、流式讲解、配图、当场问一题、记进度。  
当前产品还不能：保证理解过关、保证隔天还能提取、在遗忘前把该复习的推回来。

**「进度 100%」在现有系统里只表示「每个知识点都被点过并答过一次」。这不是学会，更不是记住。**

### 2.2 产品原则（做决策时用，不是海报）

1. **懂了才能过关。** 不能跳过检查；未掌握必须换角度再讲、再测，不能只给一句评语。
2. **记住才算学完。** 课程完成度 = 理解过关 × 记忆保持，缺一不可。
3. **只教这份资料。** 讲解、提问、卡片、测验都必须锚定用户上传的原文，禁止用模型常识顶替。
4. **考提取，不考再认。** 优先问「请讲出来 / 请填出来 / 请对比」，少用纯选择题混过关。
5. **复习不是另一套产品。** 记忆调度长在课程里：忘了就回到补讲，而不是丢进孤立的闪卡 App。
6. **少而准。** 每天只推「今天必须复习的」和「下一块该学的」，不堆功能。

## 3. 学习科学：本产品站在什么机制上

不做新理论，只把已经被大规模产品验证过的机制，收成一条学习路径。

### 3.1 学会（Comprehension / Mastery）

Bloom 掌握学习（Mastery Learning）的标准闭环：

1. 高质量初讲  
2. 形成性检查（当场知道会不会）  
3. **纠正性再教学**（换方法，不是重复原文）  
4. **平行再测**（第二套等价题，证明这次真会了）  
5. 过关后才进入下一块；已过关的给拓展，未过关的继续补

Khan Academy / Khanmigo 把这条做成「不给现成答案、用问题带学生走完认知劳动」。ChatGPT Study Mode 学了同一套苏格拉底陪练，但约束不稳，学生一逼就会直接给答案——本产品必须站 Khanmigo 这一侧：**可以提示、可以拆步骤，不可以代做。**

### 3.2 记住（Retention）

Ebbinghaus 遗忘曲线 + SuperMemo / Anki 的间隔重复：

- **主动提取**比再读有效得多（看懂 ≠ 能想起来）  
- 在「快忘但还没忘」时复习，记忆会变稳，间隔拉长  
- 2026 年成熟调度器是 **FSRS**（Anki 新用户默认；建模难度、稳定度、可提取概率），目标保持率通常设 **90%**

只做闪卡的产品（Anki、SuperMemo、墨墨）能记住，但不会先把复杂知识讲懂。  
只做讲解/摘要的产品（得到、NotebookLM 的 Audio Overview、通义听悟）能懂个大概，但不负责长期提取。

### 3.3 本产品的合成

```
理解编码（讲 + 图 + 自己组织答案）
        ↓ 过关
提取练习（卡片 / 口述 / 应用题）
        ↓ 按个人遗忘曲线调度
间隔重复（FSRS）
        ↓ 提取失败
回到补讲（不是只翻卡片背面）
```

双编码（文字 + Mermaid 图）已经有了，继续作为编码层，不作为记忆层。

## 4. 竞品地图：空白在哪

调研范围（2026）：Khanmigo、ChatGPT Study Mode、NotebookLM / Gemini Notebook、Anki / SuperMemo / FSRS 生态、Quizlet / Knowt / Brainscape / StudyGlen、得到、通义听悟、网易有道。

### 4.1 市场被切成三块，中间是空的

| 类型 | 代表 | 擅长 | 不擅长 |
|---|---|---|---|
| 苏格拉底私教 | Khanmigo、ChatGPT Study Mode | 带着想、不直接给答案 | 不能把「我这一套资料」变成课；没有遗忘调度 |
| 资料锚定助手 | NotebookLM | 基于我的 PDF/笔记出摘要、测验、闪卡、播客 | 没有掌握门槛，生成完仍靠用户自觉；SRS 弱或没有 |
| 记忆引擎 | Anki、SuperMemo、Quizlet、墨墨 | 真的能记住 | 不会讲复杂课；制卡成本高；忘了不会重新教 |
| 内容课 | 得到、极客时间 | 内容质量高 | 被动听；不考；不记 |
| 听记工具 | 通义听悟 | 音视频变摘要 | 消化资料，不负责学会记住 |

2026 年行业共识也指向同一组「真能改变结果」的能力：**资料锚定、多格式入库、高质量制卡、真正的间隔重复、可验证的掌握评估。** 成熟产品往往只占其中两块。

### 4.2 我们要占的位置

**「自己的资料 × 掌握学习私教 × 间隔重复记忆操作系统」**

一句话差异：

- 对 Khanmigo：我们教的是 **你上传的那份资料**，不是平台课标。  
- 对 NotebookLM：我们不只生成学习材料，而是 **拦住你、考你、忘了再教你**。  
- 对 Anki：你不必先会制卡；卡片从讲课与过关过程中长出来，忘了会回到讲解。  
- 对得到：不是听完就算；没有过关和复习，课程不得标「已学完」。

不跟有道拼词典，不跟学习机拼 K12 硬件，不跟 ChatGPT 拼万能闲聊。

## 5. 目标用户与使用场景

### 5.1 首要用户（P0）

**要用一套已有资料，在 1–4 周内学懂并记住的成人自学用户。**

典型资料：技术文档、内部培训、论文/书籍章节、考证讲义、自己的课堂笔记。

成功画面：两周后合上原文，仍能讲出结构、关键对比、以及「什么情况下用哪一步」；系统显示这门课的 **保持率 ≥ 90%**，而不是进度条满格。

### 5.2 次要用户（P1）

把资料变成可交付课程的培训者/讲师。他们需要：拆课质量、可分享副本、学员的「会了没有 / 还记得吗」而不是完播率。

### 5.3 非用户（明确不做）

- 需要学校合规、教师后台、未成年人防护的 K12 机构（那是 Khanmigo 的场）  
- 只想听播客式摘要、不愿答题的人（请用 NotebookLM）  
- 只背单词/题库刷题的人（请用有道/墨墨/题库）

### 5.4 关键场景

| 场景 | 用户行为 | 产品必须发生的事 |
|---|---|---|
| 今晚学新课 | 打开未完成知识点 | 基于原文讲解 → 过关题 → 过关才解锁下一课 |
| 第二天早起 15 分钟 | 打开首页 | 只看到「今日到期复习」，先清复习再学新的 |
| 一周后要用 | 合上资料仍要能讲 | 到期卡片以提取题出现；失败则补讲再进入短间隔 |
| 考前 3 天 | 指定日期 | 系统把保持率目标下的到期量提前铺开，避免最后一天爆仓 |
| 导入同事的课 | 用分享码 | 复制讲解与卡片模板，记忆进度从零开始，互不污染 |

## 6. 北星指标与成功标准

### 6.1 北星

**课程 14 日保持率（Course Retention@14d）**

一门课在「全部知识点理解过关」之后的第 14 天，用户对记忆卡片的成功提取比例。

辅助指标：

| 指标 | 定义 | 健康方向 |
|---|---|---|
| 理解过关率 | 首次讲解后，两次平行检查都过关的知识点占比 | 过低=讲课差；过高且保持率差=检查太弱 |
| 纠正后再过关率 | 第一次未过关、补讲后再测通过的比例 | 衡量「换角度再教」是否有效 |
| 复习依从率 | 到期卡片中实际复习的比例 | 低于 70% 说明推送或负担有问题 |
| 日复习负担 | 每用户每天到期卡片数 | 建议中位 < 25；持续 > 40 要限新课 |
| 幻觉投诉 | 用户标记「讲解不在资料里」 | 必须下降，这是信任底线 |

### 6.2 产品成功的验收（用户可感知）

用户学完一门课，应同时满足：

1. **能讲：** 对每个知识点，能用自己的话复述「是什么 / 为什么 / 怎么用」，系统判定过关。  
2. **能提：** 14 天后，核心卡片提取成功率 ≥ 90%（或用户设定的目标）。  
3. **能用：** 至少通过一题迁移题（换一个情境问同一原理）。  
4. **负担可控：** 日常复习可在 10–20 分钟内完成，而不是另开一场课。

旧成功标准（5 分钟拆出大纲、每点一张图、进度不丢）降为 **过程质量标准**，不再是产品成功本身。

## 7. 核心学习闭环（主路径）

把课程从「播放列表」改成「过关游戏 + 记忆操作系统」。

```
① 入库    上传资料 → 切块并保留原文锚点 → 拆成课程/章/知识点
② 诊断    可选前测：已会的标「理解过关」，只生成记忆卡，不强制再听
③ 初讲    只基于该知识点对应原文 + 图 + 类比（流式）
④ 检查    1 道提取题（口述/简答），系统判 mastered / partial / not
⑤ 纠正    未过关：换角度补讲（第二套讲法）→ 平行再测（不同题）
⑥ 过关    连续过关（或再测过关）→ 知识点状态 = 已理解
⑦ 制卡    自动抽出 3–8 张记忆卡（概念 / 填空 / 对比 / 应用）
⑧ 收口    本章结束有 3–5 题混合小测（含旧点穿插）
⑨ 调度    卡片进入 FSRS；首页出现「今日复习」
⑩ 回炉    复习失败（Again）→ 先看最小补讲，再进入短间隔，不直接标学完
```

**硬规则：**

- 未理解过关，不能把该知识点标为完成。  
- 未进入记忆调度，不能把课程标为学完。  
- 复习失败不得只展示卡片背面然后结束；默认提供 30–60 秒补讲入口。

## 8. 掌握度模型与记忆模型

一个知识点同时有两层状态，前端必须分开显示，避免「完成」一词撒谎。

### 8.1 理解状态（学会）

| 状态 | 含义 | 谁能改 |
|---|---|---|
| 未开始 | 还没讲 | 用户点开始 |
| 学习中 | 正在讲或正在答题 | 系统 |
| 需补讲 | 检查未过关 | 判题服务 |
| 已理解 | 过关检查通过 | 判题服务 |
| 理解回退 | 复习连续失败，说明当时是假懂 | 记忆服务回写 |

过关规则（P0）：

- 初讲后 1 道开放提取题；`mastered` 记 1 次过关。  
- `partial` / `not_mastered` → 必须补讲 + **另一道等价题**（禁止同一题再答一次算过关）。  
- 再测 `mastered` → 已理解；再失败 → 继续补讲，允许用户「暂时跳过但标记欠账」，欠账会进入今日任务，不能假装完成。

P1 可升级为「连续 2 次过关」；P0 先保证有再测，不要一次问答就放行。

### 8.2 记忆状态（记住）

每张卡片（不是每个知识点）独立调度。调度直接采用开源 FSRS 库（PyPI `fsrs`，open-spaced-repetition/py-fsrs），卡状态序列化存储即可——不手写简化版，避免二次迁移。数据模型仍须与 FSRS 字段对齐，便于日后用复习日志优化参数。

卡片字段（逻辑）：

- `difficulty` 难度  
- `stability` 稳定度  
- `retrievability` 当前可提取概率  
- `due_at` 下次到期时间  
- `last_rating` Again / Hard / Good / Easy  
- `lapses` 遗忘次数  

默认目标保持率 **90%**。用户可在课程设置里改为 85% / 95%（更高 = 更勤复习）。

知识点的「记住」= 其下所有核心卡的 `retrievability` 中位数 ≥ 目标。  
课程的「记住」= 全部核心卡按到期加权的成功提取率。

### 8.3 卡片从哪里来（质量决定记忆）

禁止把「整段讲解」做成一张卡。每张卡只考一个提取目标：

| 类型 | 例 | 用途 |
|---|---|---|
| 概念 | 「用一句话定义 X」 | 编码核心名词 |
| 填空 | 「Y 的三个步骤是：___」 | 程序性知识 |
| 对比 | 「A 和 B 在 Z 上的差别」 | 易混点 |
| 应用 | 「遇到情境 S 该用哪一步，为什么」 | 迁移 |
| 看图说 | 对着 Mermaid 图遮住标签提问 | 双编码提取 |

生成规则：

- 每知识点 3–8 张，宁少勿滥。  
- 必须能指回原文段落（`source_span`）。指不回去的卡不入库。  
- 用户可删、可改、可标记「这张没价值」。被删的卡永不因算法复活。

## 9. 信息架构与关键页面

四个常驻入口，首页不再是「课程仓库 + 上传」。

### 9.1 今日（新首页默认 Tab）

- 今日复习：到期卡片数、预计分钟数、开始复习  
- 今日欠账：未过关 / 跳过的知识点  
- 下一步新课：仅 1 个推荐继续的知识点  
- 若复习负担过重：提示「先清复习，暂缓新课」（可强行继续，但要说代价）

### 9.2 课程

保留现有课程卡片，但进度拆成两根：

- 理解进度：已理解 / 总知识点  
- 记忆进度：保持率（或「已记住的核心卡 / 总核心卡」）

课程不得只显示一根绿条。

### 9.3 听课

左目录 + 右讲解，保持现有骨架，增加：

- 原文抽屉：当前知识点对应的资料摘录（可点开核对）  
- 检查区：过关前不能点「下一知识点」（可「标记欠账并离开」）  
- 补讲区：第二套讲法，视觉上区别于初讲，避免用户以为卡了  
- 过关后展示「本课将记住的 3–8 张卡」预览，允许删差卡

### 9.4 复习

独立会话，默认 10–20 分钟：

1. 出示问题（不显示答案）  
2. 用户先答（输入或口头要点）  
3. 再翻出标准提取答案 + 原文锚点  
4. 自评 Again / Hard / Good / Easy（**记忆复习以用户自评为准**，FSRS 参数依赖诚实评分；模型初判仅作 P1 辅助建议，用户可改）  
5. Again → 可选「最小补讲」  

复习会话结束给出：记住了多少、忘了多少、下次高峰在哪天。

### 9.5 看板

现有全员看板保留为 P2。P0 优先 **个人掌握报告**：

- 各章理解 / 保持率  
- 最容易忘的 5 个点  
- 本周复习依从  
- 「如果考在 3 天后，现在的风险点」

公开排行容易把行为扭曲成刷课，与「记住」冲突，不能作为主激励。

## 10. 功能规格

优先级：P0 本阶段必须做，做完才称产品方向转成功；P1 增强效果；P2 以后再说。

### 10.1 P0｜资料锚定的拆课与讲解

**问题：** 现在拆课只用前 2 万字，讲课几乎只拿标题+摘要，模型容易用常识讲成「像那么回事」。用户无法相信自己学的是这份资料。

**要求：**

- 每个知识点保存 `source_excerpts`（原文切片，建议 1–3 段）。  
- 讲解 prompt 必须包含这些切片；禁止无切片开讲。  
- 超长资料按章节切块多次拆课，禁止静默截断后假装覆盖全书。  
- 前端提供「对照原文」；用户可报「讲的不在资料里」。  
- PDF 至少做到文本层提取（扫描件可 P1 OCR）。

**验收：** 抽 10 个知识点，8 个以上的关键命题能在原文中定位。

### 10.2 P0｜掌握门（过关 + 纠正再教 + 平行再测）

**问题：** 一题过关就放行；未掌握只给 `explanation` 文本，没有第二轮课。

**要求：**

- 检查题必须是提取题，题干不能靠选择题蒙。  
- 判分继续用 mastered / partial / not_mastered，但 **partial 与 not_mastered 都走补讲**。  
- 补讲是新的流式讲解，约束：「换类比、换顺序、针对学生刚才的错误，不要重复第一遍」。  
- 再测换题。  
- 未过关不能把状态写成 completed。

**验收：** 故意答错 5 次，5 次都出现不同再测题和补讲，且进度不是 completed。

### 10.3 P0｜记忆卡片 + 今日复习

**问题：** 没有任何间隔重复，第二天系统无事可做。

**要求：**

- 理解过关后自动制卡并让用户确认。  
- 首页「今日复习」为登录后第一屏（无到期则展示下一新课）。  
- 调度直接调用 `fsrs` 库（见 8.2），不用手写固定起步间隔。  
- 新课与复习抢时间：有到期复习时，听课页顶部提示「你有 N 张今天该记的」。  

**验收：** 用户今天过关一个点，明天打开产品，第一件事是复习该点的卡，而不是空白课程列表。

### 10.4 P0｜课程完成定义改写

- 个人课程页展示理解进度、记忆进度、下次复习时间。  
- 「学完」= 全部知识点已理解 **且** 核心卡至少完成一轮 3 日以上间隔的成功提取。  
- 仅听完讲解，文案只能是「已学过，尚未记住」。

### 10.5 P1｜本章收口测验与穿插

- 一章结束：3–5 题，必须混入本章旧点（interleaving）。  
- 错题回写理解回退或缩短卡片间隔。

### 10.6 P1｜考前模式

- 用户设「希望在日期 D 仍记住」。  
- 系统按目标保持率提前安排到期，避免 D-1 爆仓。  
- 给出风险清单：保持率低于目标的知识点。

### 10.7 P1｜最小补讲与看图提取

- 复习 Again 后 30–60 秒补讲（不是完整重听）。  
- 部分卡对着已有 Mermaid 图提问。

### 10.8 P1｜诊断前测

- 开课可选「我可能已经会」。  
- 通过则跳过初讲，只进制卡；失败则走正常初讲。

### 10.9 P2｜以后再做

- TTS / 播客式复习（NotebookLM 的强项，不是我们的差异化）  
- 思维导图总览  
- 语音对答  
- 多课程并行的全局复习队列优化  
- 社交排行、学习圈子  
- 原生 App

## 11. 现有系统差距（给研发的对照）

基于 2026-09 代码现状，不是空责。

| 能力 | 现状 | 目标 | 主要改动面 |
|---|---|---|---|
| 拆课 | 截断 2 万字，只存标题摘要 | 切块 + 原文锚点 | `course_service`、`lessons` 表 |

| 完成态 | `completed` = 答对一次 | 拆成理解态 + 记忆态 | `progress`、前端进度条 |
| 记忆 | 无 | 卡片表 + due 队列 + 复习页 | 新表 `cards`、新路由、新页面 |

## 13. 体验与文案约束

- 禁止用「已完成」表示只听过。可用：已理解、待复习、已记住、有风险。  
- 复习按钮文案用「开始今天的记忆练习」，不用「继续观看」。  
- 过关失败时的语气：先指出具体缺口，再补讲；禁止空洞鼓励。  
- 不靠连续登录火焰伤害用户；记忆产品的诚实激励是「你有 7 张今天不练就会掉」。  

视觉沿用 `03_UI设计规范.md` 的书房感。新增语义色：

- 已理解：现有绿色  
- 到期复习：品牌靛蓝  
- 记忆风险（保持率下降）：琥珀  
- 理解回退：红色

## 14. 范围：做什么、坚决不做什么

### 做

- 单人把一套资料学懂并记住  
- Web（已有手机浏览器访问即可）  
- 多用户隔离与课程副本分享（已有，保持）  

### 不做（本阶段）

- 不做成通用 ChatGPT  
- 不做内容平台（不生产自己的课包来卖）  
- 不做游戏化刷课排行作为主循环  
- 不做直播、不做短视频课  
- 不为了「酷」上语音，除非复习场景证明双手占用  

### 与旧 PRD 的明确翻转

| 旧 PRD | 本版 |
|---|---|
| 第一版不做多用户 | 已做，保留 |
| 成功 = 拆得快、有图、进度不丢 | 成功 = 能讲 + 14 日还能提取 |
| 测验/间隔重复放第二版 | 升为产品成立条件 |
| 看了很多没人考我 | 升级为：考过了却在一周后忘了，产品仍算失败 |

## 15. 风险与对策

| 风险 | 为什么致命 | 对策 |
|---|---|---|
| 制卡太水 | 记一堆废话，用户觉得复习无意义 | 强制原文锚点；用户可删；每点上限 8 张 |
| 检查题太弱 | 假过关 → 假学完 | 开放提取 + 平行再测；抽检人工看题质 |
| 复习负担爆炸 | 用户弃用 | 限新课；日负担提示；目标保持率可调 |
| 讲解幻觉 | 学了资料里没有的东西 | 资料锚定；「不在资料里」举报；无切片不开讲 |
| 用户讨厌被考 | 流失到 NotebookLM | 允许欠账离开，但不改完成定义；把单次检查控制在 1–2 分钟 |
| 调度算法过早复杂 | 拖死迭代 | P0 简化间隔，表结构按 FSRS 预留 |
| 公开看板扭曲行为 | 刷完课不复习 | 看板降为 P2，主激励改为到期数与保持率 |

## 16. 给设计与研发的一页摘要

**用户买的不是讲解，是两周后还在的能力。**

因此：

1. 讲课必须对着原文。  
2. 不会就不能标完成。  
3. 会了必须变成可提取的卡片。  
4. 打开产品先复习，再学新的。  
5. 忘了要再教，不是翻一张答案。  

对标策略：学 Khanmigo 的「不代做」、学 NotebookLM 的「不离开资料」、学 Anki 的「按遗忘曲线找你」，但做成 **一门课里的一条路**，而不是三个 App 来回切。

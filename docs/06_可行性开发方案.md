# 可行性开发方案（Cursor 实施规格）

> 版本：v1.0｜日期：2026-09-08｜角色：产品 + 架构
> 依据：`05_学会并记住_产品战略与PRD.md`（产品方向与验收标准，本方案不重复它）
> 读者：负责开发的 Cursor / 工程师。**本文是「怎么做」，05 是「为什么」。**

---

## 0. 可行性结论（先说结论）

| 维度 | 结论 | 说明 |
|---|---|---|
| 技术上可不可行 | **可行** | 现有 FastAPI + Vue3 + SQLite 架构无需推翻，全部改动是「增量改造」，无不可控技术债 |
| 关键算法 | **不自己造** | 间隔重复直接用成熟开源库 `fsrs`（PyPI），比手写固定间隔更省事且免二次迁移 |
| 最大风险 | 不是工程，是**判题与制卡质量** | 检查题太弱 → 假过关；卡片太水 → 复习无意义。用「原文锚点 + 可删 + 抽检」兜底 |
| 工作量 | 单人 + Cursor 约 **10–14 人日** | 分 4 个里程碑，每个里程碑结束都有一个可运行、可验收的出口 |
| 数据风险 | 低 | SQLite 加表 + 加列，全程幂等迁移，旧数据自动映射，不丢数据 |

一句话：**方向可落地，别在调度算法上造轮子，把力气花在「讲得准、考得真、卡得好」三件事上。**

## 1. 总体技术决策（一次定死，Cursor 照做）

| # | 决策 | 方案 | 理由 |
|---|---|---|---|
| D1 | 原文锚点怎么存 | `lessons` 表加 `source_excerpts` 列（JSON 数组），拆课时让 LLM **逐字摘录**原文作为锚点 | 不引入向量库，MVP 最快；「指不回去的卡不入库」有据可依 |
| D2 | 长文怎么拆 | 按标题/空行把资料切成 8000 字符块，逐块拆课，再合并去重 | 替代现在的「截断 2 万字」，不再假装覆盖全书 |
| D3 | 间隔重复 | 直接用 `fsrs`（open-spaced-repetition/py-fsrs）库，卡状态序列化存 JSON | 手写简化版后续必迁移，用库更省且质量更高 |
| D4 | 进度模型 | 拆成「理解轴」（`progress.understanding`）+「记忆轴」（`cards` 表）两层 | 单层 `status` 是当前最大技术债，必须拆 |
| D5 | 复习判分 | 记忆复习用**用户自评**（Again/Hard/Good/Easy）为主信号 | FSRS 参数质量依赖诚实自评；自动判「想没想起来」不可靠 |
| D6 | 理解判分 | 掌握门仍用 LLM 判（mastered/partial/not_mastered）+ 强制补讲 + 换题再测 | 理解类开放题 LLM 判分够用，且 05 已定义 |
| D7 | PDF | P0 用 `pypdf` 抽文本层；扫描件 P1 上 OCR | 满足 05 的「PDF 至少文本层提取」 |
| D8 | 卡片归属 | 卡片属于**学习者**（`user_id`），分享导入后每人生成自己的卡片与调度状态 | 记忆是个人私有状态，不可复制 |

## 2. 数据模型改造

> 全部通过 `init_db()` 幂等建表 + `_migrate()` 补列，跑一次即可，旧库自动升级。

### 2.1 新增表

```sql
-- 记忆卡片（记忆轴）
CREATE TABLE IF NOT EXISTS cards (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,                 -- 卡片属于学习者（分享导入后独立）
    lesson_id TEXT NOT NULL,               -- 来自哪个知识点
    card_type TEXT NOT NULL DEFAULT 'concept',  -- concept/cloze/compare/apply/figure
    front TEXT NOT NULL,                   -- 提取题面
    back TEXT NOT NULL,                    -- 标准提取答案
    source_ref TEXT DEFAULT '',            -- 原文锚点引用（摘录片段或定位）
    fsrs_state TEXT DEFAULT '',            -- FSRS Card 序列化 JSON（due/stability/difficulty/state…）
    due_at TEXT DEFAULT '',                -- 下次到期时间（ISO，冗余列供索引）
    lapses INTEGER DEFAULT 0,
    deleted INTEGER DEFAULT 0,             -- 软删，防算法复活已删卡片
    created_at TEXT DEFAULT (datetime('now','localtime')),
    FOREIGN KEY(lesson_id) REFERENCES lessons(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_cards_due ON cards(user_id, deleted, due_at);

-- 复习日志（Retention@14d 统计 + 日后 FSRS 参数优化）
CREATE TABLE IF NOT EXISTS review_logs (
    id TEXT PRIMARY KEY,
    card_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    rating TEXT NOT NULL,                  -- again/hard/good/easy
    elapsed_days REAL DEFAULT 0,           -- 距上次复习实际间隔
    scheduled_days REAL DEFAULT 0,         -- 本次调度出的间隔
    reviewed_at TEXT DEFAULT (datetime('now','localtime')),
    FOREIGN KEY(card_id) REFERENCES cards(id) ON DELETE CASCADE
);
```


### 2.4 状态机定义（Cursor 必须照此实现）

**理解轴 `progress.understanding`：**

```
not_started → learning →(过关)→ understood
                │  ↑
                └─→ needs_reteach（判 partial/not 后）──(再测过关)──→ understood
```

- 只有 `understood` 才允许「进入下一知识点 / 计为理解完成」。
- `needs_reteach` = 欠账，进入「今日任务」，可暂时离开但**不可标完成**。

**记忆轴（卡片）：**

- 新卡 → 复习评分 Again/Hard/Good/Easy → FSRS 计算 `due_at`。
- 一张卡「已settled」= 存在一次 rating ∈ {good,easy} 且 `scheduled_days >= 3`（对应 05 的「完成一轮 3 日以上间隔的成功提取」）。
- 知识点「记住」= 其下核心卡全部 settled（P0 简化）；课程「记住」= 全部核心卡 settled（P0）。
- `retrievability` 中位数等精细口径留到里程碑 C 的「保持率报告」。

**课程「学完」硬定义（前端显示依据）：**

```
学完 = 所有知识点 understanding = understood
      AND 所有核心卡 settled
否则文案只能是「已学过，尚未记住」。
```

### 3.4 `backend/app/core/`：新增 `scheduler.py`（FSRS 封装）

```python
# requirements.txt 增加： fsrs
from fsrs import FSRS, Card, Rating

_scheduler = FSRS()  # 默认参数，后续可用 review_logs 优化

def review_card(fsrs_state: str, rating: str, now=None) -> dict:
    """根据上次序列化的卡状态 + 本次评分，返回新状态 + 下次到期。"""
    card = Card.from_dict(json.loads(fsrs_state)) if fsrs_state else Card()
    r = {"again": Rating.Again, "hard": Rating.Hard,
         "good": Rating.Good, "easy": Rating.Easy}[rating]
    new_card, log = _scheduler.review_card(card, r)
    return {
        "fsrs_state": json.dumps(new_card.to_dict()),
        "due_at": new_card.due.isoformat(),
        "scheduled_days": log.scheduled_days,
        "elapsed_days": log.elapsed_days,
    }
```

> 注意：`fsrs` 库的字段/方法名以**所装版本 README 为准**（核心概念稳定：`Card` 含 `due/stability/difficulty/state/reps/lapses`，`Rating` 为 Again/Hard/Good/Easy）。第一次接入先 `pip show fsrs` + 读 README 跑通最小 demo，再封装。

## 5. 里程碑拆解（对齐 05 路线图，含验收与工作量）

### 里程碑 A — 不再假装学完（约 2–3 人日）

**目标**：答错不能靠一句评语蒙混过关；讲解对着原文。

| 任务 | 文件 |
|---|---|
| 数据层：加表/加列/迁移/状态机 | `db.py` |
| 鉴权补漏 3 个 lesson 端点 | `routes.py` |
| 拆课分块 + 原文摘录 | `course_service.py`、`schemas.py` |
| 讲课带切片 | `tutor_service.py` |
| 补讲流 + 平行再测 + gap | `tutor_service.py`、`routes.py` |
| 听课页过关锁 + 补讲区 + 原文抽屉 | `Learn.vue`、`QuestionCard.vue` |

**验收（可手动跑）：**
- 故意答错 → 出现与第一遍不同的补讲 + 一道与上一道不同的再测题；进度不是 completed。
- 连错 3 次仍无法点「下一个」（除非标记欠账）。
- 抽 1 个知识点，讲解内容能在「原文抽屉」里找到对应原文。

## 6. 风险与降级（工程侧）

| 风险 | 降级方案 |
|---|---|
| `fsrs` 库 API 与文档不符 | 接入前先 `pip show fsrs` + 读 README 跑通 demo；实在不行退回「固定间隔表 + 预留字段」作为应急（但优先用库） |
| 制卡质量差 | 强制 `source_ref`；用户可删；每点上限 8 张；里程碑 B 先只出 concept/cloze 两类，再扩 |
| 判题把「假懂」判成 mastered | 开放题 + 平行再测；里程碑 C 加抽检脚本 `scripts/eval_questions.py` 人工看题质 |
| 复习负担爆炸 | 首页显示负担提示；超过阈值提示「先清复习，暂缓新课」；目标保持率可调 85/90/95 |
| 流式补讲成本翻倍 | 补讲只讲「缺口」，prompt 限定篇幅 ≤ 300 字；正文缓存避免重复生成 |
| 旧数据迁移出错 | `_migrate` 幂等；升级前备份 `backend/data/ai-tutor.db` 一个文件即可 |

## 7. 成本与性能估算（可行性的一部分）

按 DeepSeek 现价粗略估算（每 1M token 元级，具体以当下报价为准）：

| 动作 | 估算 token/次 | 说明 |
|---|---|---|
| 拆课（分块后） | 每 8000 字块约 4–8k out | 块数 = 资料长度 / 8000 |
| 讲课（带切片） | 2–4k out | 流式 |
| 补讲 | 1–2k out | 限定篇幅 |
| 判题 | ~500 out | 结构化 |
| 制卡 | 1–2k out | 每知识点一次 |
| 复习 | 0（纯本地调度） | FSRS 不调 LLM，除非「最小补讲」 |

结论：**单用户学一门 10 万字段落课程的 LLM 成本在个位数人民币以内**，完全可行；复习环节几乎零边际成本（这正是产品护城河所在）。

## 9. 与 05 的差异点（本方案对 05 的三处落地修正）

# 多用户、学习看板与分享功能设计

## 一、功能目标

1. **注册/登录**：每个用户有独立账号，默认只能看到自己上传的课程。
2. **学习看板**：一个公开的进度看板，展示所有用户的学习进度与使用情况。
3. **分享**：用户可以把自己在学的课程分享给别人，别人可导入到自己的课程列表。

## 二、权限模型

| 对象 | 权限 |
|---|---|
| 自己的课程 | 查看 / 编辑 / 删除 / 分享 |
| 别人分享的课程 | 通过分享码导入副本到自己名下，之后等同自己的课程 |
| 学习看板 | 所有登录用户可见（展示昵称 + 聚合进度，不含课程详情隐私） |

## 三、数据模型

### users 表
```
id, username（唯一）, password_hash, nickname, created_at
```

### courses 表（新增字段）
```
+ user_id：所属用户
+ shared_from：来源课程 id（分享导入的副本，可为空）
```

### share_links 表（新增）
```
id, course_id, token（随机码）, created_at
```

## 四、鉴权方案

- JWT：登录/注册成功后签发 token（含 user_id）
- 前端存 localStorage，请求时通过 `Authorization: Bearer <token>` 携带
- 后端中间件解析 token，识别当前用户

## 五、API 设计

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | /api/auth/register | 注册（用户名+密码+昵称） | 无 |
| POST | /api/auth/login | 登录，返回 token | 无 |
| GET | /api/auth/me | 当前用户信息 | 需登录 |
| GET | /api/dashboard | 公开学习看板（所有用户进度） | 需登录 |
| GET | /api/courses | 当前用户的课程列表 | 需登录 |
| POST | /api/share/{course_id} | 生成分享链接 | 需登录 |
| POST | /api/share/import | 用分享码导入课程 | 需登录 |

## 六、前端页面

1. **登录/注册页**：两种模式切换，登录后跳首页
2. **首页**：顶部用户信息 + 退出按钮；课程卡片加「分享」按钮
3. **学习看板页**：展示各用户昵称、课程数、已完成知识点、掌握率，卡片或列表形式
4. **导入入口**：顶栏「导入分享」按钮，输入分享码导入

## 七、数据隔离要点

- 所有课程查询强制加 `WHERE user_id = 当前用户`
- 分享导入 = 复制一份课程结构到导入者名下，不共享写权限
- 看板数据只做聚合（数量/百分比），不暴露具体课程内容
